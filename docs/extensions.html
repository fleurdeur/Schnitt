Lifecycle

Install, enable, restart.

A bundle is copied into Schnitt's private files. The app reads the copied manifest; it never executes the archive.

In the app
  1. Home → Tools → Extensions. The Extensions card is the last card in Tools.
  2. Tap Import .sc and choose the bundle.
  3. Read the card. Its category, version, author and description come from manifest.json.
  4. Turn it on, then open the card and set its declared properties.
  5. Tap Restart Schnitt to apply. Restart is required because themes, icons, effects, layout and playback behaviors are read during startup.

The bundled Auto Scroll is installed once on first run and enabled. Importing another bundle with the same id replaces the files but keeps the enabled state and matching property values.

What happens on import
1. Check suffixThe picker name must end in .sc.
2. UnpackEntries are read into a private temporary directory.
3. ValidatePaths, allowlist, duplicate entries, sizes, manifest, category files and capabilities.
4. CommitThe temporary directory is renamed to files/extensions/<id>.
5. StoreEnabled state and property values are stored in Schnitt preferences.
6. RestartThe new snapshot is read by the editor, theme, catalog, icons and playback.

Remove and update

Remove deletes the private directory and its property values. Update is an import with the same id; matching property ids keep their values and the enabled flag is preserved. The version field is informational and displayed in the card; it does not control installation.

Bundle format

The .sc container.

A .sc file is a standard ZIP. The suffix is the contract; the contents are a manifest plus optional category files.

my-extension.sc              (a zip, never a renamed folder)
├── manifest.json            required
├── README.md                optional, recommended
├── LICENSE                  optional
├── LICENSE.txt              optional
├── theme.css                required for THEME
├── icons/
│   └── icons.json           required for ICONS
├── effects/
│   ├── first.json           required for EFFECTS
│   └── second.json          optional
└── layout/
    └── tools.json           required for LAYOUT

There is no nested extension folder inside the zip. manifest.json must be at the archive root.

Allowlist

Only these entries are accepted:

rootmanifest.json, README.md, LICENSE, LICENSE.txt, theme.css
icons/icons.json only
effects/up to 24 .json files
layout/up to 4 .json files

Everything else is rejected: APK, ZIP, DEX, JAR, SO, JS, HTML, CSS outside theme.css, SVG, PNG, hidden metadata and nested executables.

Contract

manifest.json field by field.

Unknown keys are ignored. Unknown values for the fields below fail the install.

{
  "schema": 1,
  "id": "my-extension",
  "name": "My Extension",
  "version": "1.0.0",
  "author": "your-name",
  "description": "One sentence that appears in the extension card.",
  "category": "behavior",
  "capabilities": ["timeline.follow"],
  "properties": [
    { "id": "enabled", "label": "Enabled", "type": "toggle", "default": true }
  ]
}
schemaRequired integer. Must be 1; another schema is refused with an unsupported version error.
idRequired. Lowercase a-z, digits, dot, underscore or dash. Pattern [a-z0-9][a-z0-9._-]{1,63}. This is the storage folder and the stable update key.
nameRequired, up to 64 characters. Shown in the Extensions list and card.
versionOptional display string, up to 24 characters. Defaults to 1.0.0. No semver enforcement.
authorOptional, up to 64 characters. Shown next to category and version.
descriptionOptional, up to 400 characters. Shown when the card is expanded.
categoryRequired. One of behavior, theme, icons, effects, automation, layout. Controls the app filter and which files are required.
capabilitiesOptional string array, maximum 8. Closed allowlist: timeline.follow, theme.css, icons.home, effects.custom, layout.tools, automation.safe. An unknown capability fails the install.
propertiesOptional array, maximum 24. Each entry uses the property schema below. Ids must be unique inside the bundle.
How mapping works

Extension data to app target.

This is the important part: an extension is not a script. The app reads specific data and maps it to a specific surface.

manifest.categoryExtensions screen filter and card label. It does not automatically grant a behavior; capabilities do.
capabilities[]Allowlist of readers. Each capability maps to one documented area below.
theme.cssMapped to Palette fields, then to Am.palette. This affects all Compose surfaces that read Am.*.
icons/icons.jsonMapped to HomeIcons.custom(name, fallback) at the four Home bottom-bar buttons and the Extensions tool card.
effects/*.jsonParsed as EffectDefinition, appended to the normal effect catalog under Imported.
layout/*.jsonReads toolsColumns, then passes it to the Tools grid column calculation.
automation.safeReads the loopPlayback property and enables the existing playback loop branch.
timeline.followReads the Auto Scroll property IDs and drives the timeline's vertical follow animation.

Category requirements

behaviorNeeds timeline.follow.
themeNeeds theme.css.
iconsNeeds icons/icons.json.
effectsNeeds 1–24 files in effects/.
automationNeeds automation.safe.
layoutNeeds 1–4 files in layout/.

What is not mapped

Arbitrary property ids are displayed and stored but do nothing unless a capability reader knows them. There is no general-purpose scripting hook, no DOM, no WebView and no callback from the property screen into app internals. This is deliberate.

If you add a new property for a future reader, keep its id stable. Renaming an id makes it look like a new property and its saved value starts from the new default.

Custom controls

Property schema and storage.

Properties are how an extension becomes configurable without shipping code. Schnitt renders the controls, stores the strings and exposes them to the matching reader.

{
  "id": "speed",
  "label": "Scroll speed",
  "type": "slider",
  "default": 1.0,
  "min": 0.25,
  "max": 3.0,
  "step": 0.05
}
idRequired. Must match [A-Za-z][A-Za-z0-9_.-]{0,47} and be unique in the bundle.
labelOptional display label, up to 64 characters. Defaults to the id with underscores replaced by spaces.
typeRequired. toggle, slider, choice, text or color.
defaultType-specific default. Toggle is boolean. Slider is a number. Choice must be one of values. Text/color is a string.
min / max / stepSlider only. Min and max must be finite; max is forced above min; step must be positive. Values are clamped when read.
optionsChoice only. 1–24 human-readable labels shown as chips.
valuesChoice only. Same length as options; these exact strings are stored and read. If omitted, labels are used as values.

Built-in reader keys

enabledBehavior master switch. Missing means enabled.
modeChoice with values playing and selected. Defaults to playing.
snapToggle. Centre the active row when true; use the 24–76% comfort band when false.
speedNumber, 0.1–4.0; used as the Auto Scroll easing multiplier.
smoothnessNumber, 60–2000 ms; base Auto Scroll easing duration.
toolsColumns / columnsLayout fallback when no layout JSON provides a value. Clamped to 1–3.
loopPlaybackAutomation toggle. True restarts playback at the scene end.

Storage details

Values are stored as strings in Schnitt's private preferences under the bundle id and property id. The UI clamps sliders and resolves choices to the stored value; the reader also clamps again, so a hand-edited preference cannot produce an out-of-range speed.

The property screen is scrollable, survives updates with matching ids, and resets to the manifest default when the id changes or the extension is removed. Property values are never written into project files.

Bundled behavior

Auto Scroll in depth.

Auto Scroll is the reference behavior extension. It shows exactly how a property set maps to a real, bounded app animation.

What it reads

enabledIf false, the timeline does not follow.
mode=playingAt the current frame, choose the visible layer with the latest start time. Among equals, the later layer in the scene wins. Hidden layers and layers outside startTime..endTime are ignored.
mode=selectedUse state.selectedId instead of the active-layer lookup, so the selected row stays visible while playback runs.
snap=trueScroll so the row is centred in the visible timeline rows.
snap=falseScroll only when the row leaves the band between 24% and 76% of the visible rows. This is the gentler mode.
speedDuration is smoothness / speed, clamped to 60–4000 ms. It does not touch the playback clock.
smoothnessBase easing duration in milliseconds.

What it changes

Only TimelineView.scrollPx. It never writes the scene, a layer, a keyframe, state.frame, state.playing, audio, export settings or project XML.

The behavior collects the active layer id with snapshotFlow, stops at distinctUntilChanged, and starts one tween per row change. A new row cancels the previous tween and retargets from the current scroll. Manual timeline scrolling still works and cancels the animation through the normal gesture path.

When playback stops, the follow loop stops. The final eased scroll may finish; no playback state is changed.

{
  "schema": 1,
  "id": "auto-scroll",
  "name": "Auto Scroll",
  "version": "1.0.0",
  "author": "fleurdeur",
  "description": "Keeps the timeline on the layer that is playing.",
  "category": "behavior",
  "capabilities": ["timeline.follow"],
  "properties": [
    {"id":"enabled","label":"Follow during playback","type":"toggle","default":true},
    {"id":"mode","label":"Follow","type":"choice",
     "options":["Playing layer","Selected layer"],"values":["playing","selected"],"default":"playing"},
    {"id":"snap","label":"Snap layer to centre","type":"toggle","default":true},
    {"id":"speed","label":"Scroll speed","type":"slider","default":1.0,"min":0.25,"max":3.0,"step":0.05},
    {"id":"smoothness","label":"Smoothing time","type":"slider","default":260,"min":80,"max":1200,"step":20}

Theme category

CSS mapped to the palette.

Theme extensions use a deliberately small CSS reader. They can set palette colours; they cannot inject layout CSS, selectors, images or JavaScript.

/* theme.css */
:root {
  --home-bg: #0b0f0c;
  --card: #121a15;
  --navy: #e6f2e9;
  --home-ink: #cfe0d5;
  --accent: #7ed9a0;
  --accent-deep: #183326;
  --timeline-bg: #080b09;
  --preview-bg: #050706;
}
Manifest 
{
  "schema": 1,
  "id": "night-garden",
  "name": "Night Garden",
  "category": "theme",
  "capabilities": ["theme.css"]
}

Parser rules

  • Comments are stripped. Only --name: value declarations are read; selectors and other CSS are ignored.
  • The last valid declaration for a name wins.
  • Accepted colours: #RGB, #RRGGBB and #AARRGGBB (alpha first). Invalid colours are ignored.
  • Kebab-case is converted to the palette name: --home-bg → HomeBg.
  • Camel-case is accepted directly: --HomeBg also works.
  • Names outside the palette are ignored. --bad: red, url(...), @import and selectors do nothing.
  • Only enabled theme extensions are concatenated, in installed order. The base theme is applied first, then the extension overrides.
  • Theme changes apply after restart because the palette is built when AppSettings starts.

Icons category

Path data for named buttons.

An icon extension replaces a logical button icon. The app supplies the fallback, so an invalid path cannot leave a button empty.

// icons/icons.json
{
  "home.projects": {
    "path": "M5 3h14v18H5Z M9 8h6 M9 12h6 M9 16h4",
    "stroke": true,
    "width": 1.8,
    "mirror": false
  },
  "home.tools": "M4 12h16 M12 4v16"
}
Manifest 
{
  "schema": 1,
  "id": "line-icons",
  "name": "Line Icons",
  "category": "icons",
  "capabilities": ["icons.home"]
}

Supported names

home.projectsHome bottom bar, Projects.
home.pluginsHome bottom bar, Plugins.
home.templatesHome bottom bar, Templates.
home.toolsHome bottom bar, Tools.
tools.extensionsThe Extensions card in Tools.

A value may be a plain string (a stroke path) or an object with path, stroke (boolean), width (0.5–6) and mirror (boolean). A missing object means stroke is true and width is 1.8. Paths are SVG d data; < and url( are rejected. Invalid path data falls back at render time.

Effects category

A complete effect definition.

Each JSON file is parsed by the same effect parser as the built-in library. It gets editable properties, keyframes, presets and its own shader.

How an extension effect is mapped

Bundle fileEvery effects/*.json is parsed once, in filename order, up to 24 files.
Catalog idext.<extension-id>.<effect-id>. This prevents an extension from replacing a built-in effect.
Catalog keyext-<extension-id>-<effect-key>. The key is also used as the stable effect page key.
CategoryForced to custom in the catalog and shown under Imported; the JSON still needs a valid source category.
StatusMalformed files are skipped and logged under the Extensions log tag. They do not crash the catalog.

Top-level JSON fields

idRequired. Unique inside the bundle; used as the id suffix. Use lowercase letters, digits and dashes.
nameOptional display name. Defaults to the id.
categoryRequired and must be one of: color, blur, distort, stylize, noise, repeat, key, move, beat, 3d, text, other, external, custom.
descriptionOptional description shown in the effect browser.
skslRequired for a shader effect. The complete SkSL source with the shader contract below.
nativeOptional boolean. Reserved for the app's built-in native effects. Extension effects should omit it or set false; a native extension effect has no executable code path.
sinceOptional version label. Extension effects default to the bundle version.
paramsOptional array of parameter objects. Each non-text parameter becomes a uniform with the same id.
presetsOptional array of named presets.
shortcutsOptional array of additional catalog tiles that point at the same shader with different names and descriptions.

Parameter fields

idRequired. Becomes the property name and shader uniform name. Letters, digits and underscore; start with a letter.
labelOptional UI label.
typefloat, angle, point, point3, hue, color, switch, choice or text.
defaultFloat/angle/switch number or boolean; [x,y] for point; [x,y,z] for point3/hue; a choice value; #RRGGBB/#AARRGGBB for colour; a string for text.
min / max / stepNumeric range and UI step. The UI uses these; defaults should be inside the range.
options / valuesChoice only. Labels and the numeric values written into the effect. They must have the same length.
percent / pixels / unitUI hints. percent shows a percent suffix; unit appends a label; pixels changes display formatting.
layerTimeNumber is limited by the layer duration.
afterId of an earlier numeric parameter; this parameter cannot go below that value.
legacyDefaultFallback default for old project files that do not contain the property.
whenShow this control only when another property equals one of the listed integer values: {"style":[1,2]}.
paletteText only. Shows the app palette picker.
slowInteger 1–20; slower slider sensitivity.

Choice values are stored as their actual values entry, not as the chip index. Keep choice values stable across updates. Text parameters do not create a shader uniform.

Shader contract

An extension effect shader must declare image, size and time, and must define half4 main(float2 pos). Numeric parameters become uniforms with the same type. The app supplies size (layer size) and time (layer-local time); read the source with image.eval(pos).

{
  "id": "my-lens",
  "name": "My Lens",
  "category": "distort",
  "description": "A small radial lens with a strength control.",
  "params": [
    {"id":"strength","label":"Strength","type":"float","default":0.5,"min":0.0,"max":1.0,"step":0.01}
  ],
  "sksl": "uniform shader image; uniform float2 size; uniform float time; uniform float strength; half4 main(float2 pos) { float2 uv = pos / size; float2 d = uv - 0.5; float r = dot(d,d); return image.eval(pos + d * r * strength * 40.0); }"
}

SkSL on strict ES2 devices needs constant loop bounds. Use a fixed maximum and a break, for example for (int i=0; i<64; i++) { if (i >= count) break; ... }. Do not declare pos yourself. Avoid texture reads outside the layer; the engine expects an effect image. A malformed shader is skipped by the catalog, not installed as a native path.

Presets

"presets": [{
  "name": "Soft",
  "params": {
    "strength": 0.35,
    "center": [0.5, 0.5],
    "phase": [[0.0, 0.0], [1.0, 1.0, "ease"]]
  }
}]

A scalar becomes a static value. An array of [t, value, easing?] arrays becomes keyframes. Time is normalized; the app fits preset keys to the layer duration.

Shortcuts

"shortcuts": [{
  "key": "lens-soft",
  "name": "Soft Lens",
  "description": "A softer lens tile.",
  "since": "1.0.0",
  "also": ["distort"]
}]

also adds extra catalog categories. Every category in it must be a valid effect category.

Layout category

A narrow, usable layout surface.

Layout extensions are intentionally limited. They cannot position arbitrary controls or cover the editor.

// layout/tools.json
{
  "surface": "tools",
  "toolsColumns": 2
}
Manifest 
{
  "schema": 1,
  "id": "two-column-tools",
  "name": "Two Column Tools",
  "category": "layout",
  "capabilities": ["layout.tools"],
  "properties": [
    {"id":"toolsColumns","label":"Tools columns","type":"slider","default":2,"min":1,"max":3,"step":1}
  ]
}

Mapping

The last enabled layout extension's layout JSON is read. If it has toolsColumns in 1–3, that wins. Otherwise the reader falls back to the manifest property toolsColumns or columns. If neither exists, the normal responsive column calculation is used.

Only the Tools grid is affected. The editor, timeline, project list, export screen and dialogs do not move. Other layout JSON keys are ignored. Values outside 1–3 are ignored.

The JSON is still required by the installer for a layout category, even when the manifest property provides the fallback.

Automation category

Small, predictable playback rules.

The safe automation reader currently supports one action: loop at the scene end. It is a real playback branch, not a script.

{
  "schema": 1,
  "id": "loop-playback",
  "name": "Loop Playback",
  "version": "1.0.0",
  "category": "automation",
  "capabilities": ["automation.safe"],
  "properties": [
    {"id":"loopPlayback","label":"Loop at scene end","type":"toggle","default":true}
  ]
}

The reader looks for an enabled extension with automation.safe and a true loopPlayback value. Missing property means off. The existing playback loop branch then restarts at frame 0 at the end. It does not alter audio, keyframes, speed curves, the scene duration or export.

Security model

What the reader refuses.

The extension system is a parser, not a plugin runtime. This is the security boundary.

01

Allowlist

Only manifest, README, license, theme.css, icons/icons.json, effects/*.json and layout/*.json. Everything else is rejected, including images and hidden metadata.

02

Paths and archives

Absolute paths, .., backslashes, colons, NUL, duplicate entries, oversized entries and archives over the total cap are rejected before commit.

03

Data, never code

No JavaScript, DEX, JAR, native library, shell command, WebView, network request or internal file read. Extensions live in their own files/extensions/<id> directory.

Threat model details

  • The bundle is not signed. Schnitt validates structure, not identity. Download from authors you trust and read the README.
  • Theme CSS cannot contain url(), @import, selectors or HTML; only palette hex declarations are read.
  • Icon paths are vector data, not markup. Invalid paths fall back to the built-in icon.
  • Effect JSON is shader source. It runs on the normal GPU engine and is not a native code path, but a pathological shader can still be expensive. Keep effects bounded.
  • Property strings are capped at 512 characters. Sliders are clamped again when read, so editing preferences by hand cannot create an unbounded behavior.
  • The extensions directory is private app storage. Other apps cannot read it without root or a Schnitt bug.
Build the archive

Zip it without a parent folder.

The most common install failure is a zip that contains a folder wrapper instead of manifest.json at its root.

macOS / Linux 
cd my-extension
zip -r ../my-extension.sc \
  manifest.json README.md theme.css \
  icons effects layout
Windows PowerShell 
Compress-Archive -Path manifest.json,README.md,theme.css,icons,effects,layout `
  -DestinationPath my-extension.zip
Rename-Item my-extension.zip my-extension.sc
Check the root 
unzip -l my-extension.sc

The output should start with manifest.json. It must not start with my-extension/manifest.json.

Remove .DS_Store, __MACOSX, Thumbs.db and editor backups. They are not on the allowlist and cause an install error.

A zip with the wrong suffix is refused. Rename the archive after compression; do not rename a folder.

Evolution

Keep ids stable.

Updates are identified by manifest.id, not by filename or version.

Update rules

  • Keep the same id to update in place. The enabled flag is preserved.
  • Keep property ids stable to preserve values. Renaming an id starts that control from its new default.
  • Changing category is allowed but the card and required files change; re-test.
  • version is a display string. Semver is recommended, not enforced.
  • New effects get new catalog ids; removing an effect used by a project leaves the project effect unresolved, so keep backward-compatible effect ids.
  • Changing a theme's palette keys is safe; removed keys return to the base theme.

Schema future

The reader only accepts schema 1. A future schema will be rejected by older app versions rather than guessed. When a new capability is added, older versions reject it because capabilities are a closed allowlist.

This is why the extension reader is predictable: an old app refuses what it does not understand instead of running it partially.

Deliberate limits

What is not in the contract.

These are not missing features waiting to be enabled. They are outside the current safe reader.

  • No executable code. No JavaScript, DEX, JAR, native library, shell command, WebView, network access or internal file reads.
  • No full CSS themes. Only palette colour variables. No selectors, fonts, spacing, images, animations or layout rules.
  • No arbitrary icons. Only the four Home bar names and tools.extensions. Path data only, no images or markup.
  • No editor layout redesign. The layout reader only changes the Tools column count; it cannot move, hide or resize editor controls.
  • No scripting automation. The only safe automation action is looping playback at the scene end.
  • No custom property bindings. A property that no reader knows is stored and displayed, but it does not execute an action.
  • No extension store or signature. Bundles are local files. Install trusted authors and read the manifest.
