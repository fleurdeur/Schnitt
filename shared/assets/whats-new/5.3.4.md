# What's new in 5.3.4

**Reverse now selects an encoder resolution that the phone actually supports, encrypted plug-in archives ask for their password with a progress bar, and the plug-in property/preview layout is separated from the floating window.**

## New features
- **All H.264 encoder paths** - reverse and GIF encoding now probe every H.264 encoder and choose an even, aspect-preserving size that the device advertises.
- **Portrait and unusual ratios** - 1920x1080, 1080x1920, 720x1280, 1:1, 4:3 and custom ratios fall back to supported encoder sizes instead of failing.
- **Encoder fallback** - hardware encoders are tried first, then other advertised H.264 encoders, with a minimal format retry if colour metadata is rejected.
- **Reverse memory cache** - short clips are reversed from RAM instead of being written to and read back from a temporary YUV file.
- **HLSL and WGSL import** - common single-image HLSL and WGSL shaders are translated to SkSL during import, off the render thread.
- **Reverse quality** - packing, scaling and depth of the reversed output follow the chosen encoder size.
- **Encrypted plug-in prompt** - ZIP, ZXP and 7z imports now ask for a password when the archive is encrypted.
- **Import progress** - the plug-in window shows reading progress while the archive is unpacked.
- **Wrong-password retry** - an incorrect password returns to the prompt instead of failing silently.

## Fixed
- **Unable to process this media** - reverse no longer assumes the source resolution is encodable.
- **Reverse encoder crash** - a missing H.264 size no longer reaches `MediaCodec` as an invalid format.
- **Plug-in properties conflict** - properties have one scrollable section, separate from the panel and the generated effect controls.
- **Minimized plug-in window** - the minimized bar remains anchored to the upper corner instead of inheriting the floating window position.

## Improved
- **Device-aware export** - the encoder picker respects width/height alignment and frame-rate capability.
- **Import feedback** - progress and password state are visible in the plug-in window.

## Limits
- Reverse still requires an H.264 encoder advertised by the device.
- The password prompt accepts archive passwords only; it does not bypass encrypted payloads.
